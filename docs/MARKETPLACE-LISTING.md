## Long description *(Markdown, paste into the Description field)*

Fixor is an AI-native security reviewer for GitHub pull requests. Install it once on a repo or org, and every PR gets:

- **A structured review comment** with each finding's file, line, severity, and remediation steps.
- **A SARIF + PDF report** linked from the comment — share the PDF with your team or attach it to a compliance ticket.
- **Precise, framework-aware explanations and remediation steps** generated by Claude, not regex. Fixor reasons about Express routing, auth-middleware patterns, Prisma/Drizzle ownership scoping, role-guard conventions, and env/secret handling.

Fixor is a high-signal second reviewer: every finding comes with a precise explanation and remediation steps, so you can judge it quickly. Pair it with human review rather than relying on it as a guarantee.

### Detectors shipping today

Five measured, stability-validated business-logic detectors:

- **Authentication bypass** — weakened or short-circuited auth checks (role-to-admin fallbacks, swallowed token verification, hardcoded bypass flags)
- **IDOR** — resource access without an ownership check
- **Weak admin check** — privilege gated by hardcoded email/role allowlists or client-supplied role
- **Env exposure** — secrets leaked through environment variables into response bodies
- **Secrets exposure** — hardcoded API keys, tokens, and credentials

### Why Fixor runs alongside Snyk and Semgrep

Snyk and Semgrep cover dependency CVEs and known injection patterns. Fixor covers the class pattern-matchers structurally can't — business-logic flaws in your own code that need reasoning about auth, ownership, and roles. Run both.

- **Zero setup.** Install the app, open a PR, get a review. No CI step, no IDE plugin, no rule tuning to start.
- **Claude-powered context.** Findings reason about your specific code, not just patterns — each with a precise explanation and remediation steps you can act on.
- **Cost cap built in.** Each org has a hard monthly Anthropic budget. Fixor stops scanning before it blows your bill, never after.
- **A real dashboard.** Per-org scan history, settings (severity threshold, ignored globs, detector allowlist, Slack webhook), trends widget, billing.

## Permissions justification

When the App permissions form asks "why do you need this?", paste the matching line:

| Permission | Why we need it |
|---|---|
| Pull requests: **Read & write** | Read the diff for analysis; post the review comment with findings + report links. |
| Contents: **Read-only** | Fetch the changed files to provide framework-aware context for fixes. |
| Metadata: **Read-only** | Required by GitHub for any App. |
| Webhooks: `pull_request` (opened, synchronize, reopened) | Trigger the security scan when a PR is opened or updated. |
| Webhooks: `installation` (created, deleted) | Provision / clean up the org row in Fixor's database. |

Fixor never reads issues, discussions, releases, secrets, or actions. The dashboard reads only the user's installation list (via Clerk's GitHub OAuth) — it never holds a long-lived GitHub token.

## After submission

GitHub Marketplace review takes 1–2 weeks. Common rejection reasons:
- Privacy policy missing or doesn't mention what data is processed
- Screenshots show placeholder data (`foo@bar.com`, `lorem ipsum`) — use real-looking content
- Listing claims a feature the App doesn't actually deliver yet
- The free tier claim doesn't match what users see post-install
