# Route map, milestone 1 (Express family) on the development set, 2026-10-05, $0

Pre-registration: `route-map-prereg-2026-10-04.md`. **This is the development run, not the
measurement.** The 22 cases are the ones the extractor is built against (section 2.1); nothing here
is a result on the measurement set, and no number here may be cited as detection. Zero model calls,
zero API keys. Each case's parent tree was fetched shallow from GitHub (fix and parent only) into a
work folder beside the repository; the maps stay there. The committed record,
`m1-dev-run-2026-10-05.json`, holds per-case flags, counts and digests only: no path from a reviewed
repository, no route string, no symbol.

## What milestone 1 is

`src/test/lib/route-map.ts` (pure), `src/test/route-map.ts` (entry, with the two-process C4 check),
`src/test/measure-route-map-dev.ts` (this run's scorer), `src/test/test-route-map-rehearsal.ts`
(keyless, in `test:ci`) over `fixtures/route-map/basic` (synthetic, no third-party code). The
extractor parses every non-test source file with the `typescript` parser, no type checker;
discovers Express-family route calls (`receiver.get|post|...(path, ...)`, `receiver.route(path).get`,
chained koa-router calls, Fastify option objects, Hapi `server.route({...})`); composes paths through
`use(prefix, router)` mounts across files by resolving relative imports and `tsconfig` path aliases;
builds the guard chain as mount-level, router-level and route-level middleware in order; resolves
the handler through imports, object members, class members and wrapper calls; follows calls from the
handler through relative imports to depth 3; and records data-access symbols from the frozen list.
`this.<field>.<method>()` is not resolved (section 3), by design of milestone 1.

**Against the pre-registration's bar, read honestly.** Section 5 needs C2 on 80% of in-scope cases
on the measurement set. Of these 22, about 15 are Express-family applications; milestone 1 resolves
6 of them, roughly 40%, and 6 of 22 overall. Milestone 1 is not near the bar. The run says three
things: the map builds and is deterministic on real trees of 19 to 14,433 files (the largest took
20 seconds); the Express discovery, mounting and guard chain work where the application is plain
Express with function handlers; and **the single largest cause of a miss in scope is class-based
dispatch**, present in 5 of the 9 in-scope misses (directus, oneuptime, unleash, backstage,
parse-server), where the defect sits in a service or router class reached through `this.<field>`
and milestone 1 stops at the class boundary. The other in-scope misses are a framework convention
(apostrophe's `apiRoutes` members), a hunk outside any function (signalk), and a four-hop chain
through GraphQL (erxes).

Guard-blindness (section 4 C5) is visible already: `noGuard` is above half of the routes in 13 of
the 21 trees with routes, which on the measurement set would trip falsification arm B. Milestone 1
sees guards only on the receiver's own `use()` and on the mount; app-level middleware registered in
a file other than the mount's, and framework-level auth (Fastify plugins, NestJS guards), are not
seen yet.

## One deviation from the pre-registration's text, recorded

Section 3's role heuristic is written case-sensitively (`/admin|role|.../`). Names such as
`requireRole` and `isAdmin` carry the word capitalised, so the implementation matches
case-insensitively, keeping `can[A-Z]` as written. The heuristic is descriptive and never gating
(section 4 C3), so this changes no verdict; it is recorded so the measurement reads the same
heuristic the code runs.
